## 五、一处 harness 分类器缺陷（本轮新发现，可复现）

`chess-best-move` 在 `failures.json` 被标成 `infra`。真实成因是：两次 `transport` 抖动（174.6s + 120.0s）吃掉 900s 预算后，pier 在 run deadline 处 kill 了 agent 进程（`NonZeroAgentExitCodeError`，`deliveryTerminalCause=run-deadline`，stdout/stderr 均 None）。

被误判的原因在 `scripts/frontier-harness-failures.mjs` 的 infra 正则：

```js
if (/Docker|compose|image|container|agent setup|install-cli\.sh/iu.test(message)) return "infra";
```

`message` 由 `exception.type + exception.message + trialExceptionText` 拼成，而异常消息里**内嵌了整条任务指令**，指令原文含 "The file chess_board.png has an **image** of a chess board"。用同样的字符串在本机复跑该正则：`matches infra regex: true -> image`。也就是说：任何原文含 "image"（或 "container"、"compose"）这类常见词的题目，一次 deadline kill 就会被记成 infra。

这条只影响 `failures.json` 的**分类标签**，不影响 `report.json` 的 disposition/rewards/pass@1（那些来自 verifier）。它值得单独修，因为下游拿着 `byStage` 做归因时会把"预算被传输吃掉"读成"基础设施故障"。
