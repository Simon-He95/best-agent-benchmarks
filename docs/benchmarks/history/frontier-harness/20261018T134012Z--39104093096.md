1. **本 run 不是可评分的 pass@1 run**：5 项验收 4 通过 1 失败（`verdicts.complete` 失败于 5 个 `error` 格），`capabilityMeasurement=false`、`scoreable=false`、**`passAt1=null`**。raw 63.3%（19/30）与 valid-cell 76.0%（19/25）是本 run 的可见读数，都不作为 pass@1 发布，也没有进入任何榜单/field comparison。
2. **5 个无判定格的全部原因已机械归因**：public.ecr.aws 的 `swe-bench-202605` 镜像 429 `toomanyrequests: Data limit exceeded`，发生在模型调用之前，五格耗时 5–7 秒、无 evidence 文件、无 attempt。这不是任务失败，也不是能力信号。
3. **无 recovery 被派发**：按仓库规则，pre-model 环境失败且无 canonical verdict 的格可由 recovery 批次补测，但必须先冻结 recovery manifest 并取得用户明确授权；本 run 不做这件事——没有重跑任何格、没有替换任何判定。
4. **候选二进制不可逐字节复现**：本轮 binarySha256 `7e4677bee677…` 与同一 commit 的 smoke 构建（`e3b107f9e957…`）不同；`config` 只钉 sourceCommit（`02117de8c`）。
5. **三处诚实折扣**：(a) 5 格无判定使本轮不能给出 pass@1；(b) 4 个 provider 格的 reward 0 是在模型完成前被 transport 截断后的判定，不是干净能力证据；(c) 与 38214103321 的对比是 261 commit 候选增量 + 限流 + 方差的三重复合。
6. **官方预算未被改动**：`fh_agent_timeout_multiplier=1`，逐题 `effectiveAgentTimeoutSec` 与本语料的官方值一致（600/900/1200/1800/5400，与 baseline 逐题相同），per-call 上限 1,800,000ms；报告 `budgetExhausted=0`。
7. **证据位置**：artifact `frontier-harness-report-39104093096`（含 `report.json`、`report.json.md`、`failures.json`、`failures.md`、`expected-tasks.txt`、30 题 frozen 记录与 `jobs/` 原始证据，81,776,568 字节）与每题独立的 `frontier-harness-task-39104093096-<task>`（30 个，合计 3,329,712,337 字节；90 天保留）；本 run 全部 33 个 artifact 合计 3,519,757,347 字节（另含 candidate 108,264,454、corpus 3,988）。本记录只取聚合报告逐字（sha256 见上），未改动任何 per-task 记录。
