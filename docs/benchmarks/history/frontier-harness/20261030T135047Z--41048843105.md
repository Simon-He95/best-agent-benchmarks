## 3. 15 个未通过格的机械归因

workflow 自己的 failure analysis 把这 15 格分成 **4 格 `model`** 与 **11 格 `inconclusive`**；以下是它记录的机械事实，不改变任何判定。

**A. 空 patch 类（datacurve，7 格）** — `arktype`、`expr`、`fastapi`、`katex`、`meriyah`、`python-statemachine`、`scc`。
每格的 `artifacts/model.patch` 都是 **0 字节**，而 p2p 全通过（f2p 0/N）。这正是清单 `knownRisks.emptyPatchCaptureGap` 披露的机制：datacurve 的 collect 钩子取 `base..HEAD`，模型改了文件但没提交，于是判分对象是原始树。对照：同批通过的 `httpx` patch 为 31,828 字节。7 格中 6 格同时是"预算到点停止"，`arktype` 则在 5,036 s 内 completed 后仍是空 patch。

**B. 预算到点、产物缺失/不完整（terminal-bench，5 格）** — `build-cython-ext`、`chess-best-move`、`code-from-image`、`gcode-to-text`、`largest-eigenval`。
每格都在各自声明预算边界被停（873–881 s 与 1,174 s，对应 900 s 与 1,200 s 上限），verifier 随后找不到要求的产物：`move.txt`、`output.txt`、`hello.txt` 缺失，Cython 编译模块未生成（9 failed / 2 passed），largest-eigenval 的 `test_speedup` 有 3/27 未达标。

**C. 已完成但 verifier 判 0（3 格）** — `dna-insert`（Tm 差 5.72 °C）、`openssl-selfsigned-cert`（6 项里 1 项失败）、`polyglot-c-py`（多留了 `cmain`）。这三格是干净的模型结果，没有任何基础设施疑点。

**关于 `stopped` 与 `budgetExhausted=0` 的口径**：11 个 `stopped` 格的异常是 `NonZeroAgentExitCodeError`（容器内 `v3 run cancelled: stopped`，CLI 退出 1），不是 Pier 的 `AgentTimeoutError`，所以报告里 `budgetExhausted` 计数为 0。它们是"CLI 把自己的尝试跑到声明预算并被自己停下"，时长与预算边界吻合（datacurve 5,399–5,439 s / 5,400 s；terminal-bench 873–881 / 900、1,174 / 1,200）。

**transport 明细（不改判定，仅披露）**：30 格中 13 格各记录了 **1 次** `model-failure`，reason 均为 `transport`，其自身 `durationMs` 为 24.7–226.0 s。其中 11 格属于上面的 A/B 类（失败），2 格是 `sanitize-git-repo` 与 `regex-log`（仍通过）。占比最高的是 `chess-best-move` 226 s / 900 s（25%）与 `build-cython-ext` 164 s / 900 s（18%），datacurve 各格均在 4.2% 以内。**本轮不把 transport 记为任何一格的失败主因**：每格的直接机械成因都在其 patch 字节或 verifier 输出里；也没有任何格子因此获得第二次尝试。

## 4. 这个读数能说什么、不能说什么

- **能说**：在最新的、CI 可检出的 best-agent main（`f5729b779` / 0.0.18）上，这份冻结 30 格 corpus 的一次性 pass@1 是 **0.5（15/30）**，30 格全部有判定，候选与 instruction 均单值冻结。
- **不能说**：它是相对 0.6 的"能力回退"。候选差量是 81 个提交、174 个文件（含 spec 507 把 `shell` 并入单一 `exec`：smoke 实测线上 28 个工具、无独立 shell），并且 9 格翻转里既有从失败变通过（`httpx`、`regex-log`、`sanitize-git-repo`），也有从通过变失败（`katex`、`scc`、`build-cython-ext`、`code-from-image`、`openssl`、`polyglot`）。按清单冻结的判读规则，逐格差异只能读成"候选差量 + provider 条件 + 运行间方差"的合成，不能归给单一改动。
- **不能**：把 11 个 `inconclusive` 格当成纯粹的模型能力读数——它们的证据不足以证明单一成因；也不能把它们当环境故障去重跑：它们都已有 canonical 判定，AGENTS.md 的 recovery 通道只对"无 prediction"的格子开放。
