## spec 237（process handle）的目标缺陷：本轮的机械实测

spec 237 的动因是冻结证据里"模型无法可靠复述 37 字符 `processRef`"。用同一口径（每题最后一次 model-request 的 messages，按 callId 去重后统计 tool result）机械统计两轮：

| 指标 | 35992545942 (beta.33，无 handle) | 36092882496 (beta.34，有 handle) |
| --- | --- | --- |
| 伪造 `processRef` 拒绝（`must be a processRef returned by process-start`） | **9 次 / 3 题**（regex-log 4、merge-diff-arc-agi-task 3、gcode-to-text 2） | **0 次 / 0 题** |
| 非法 handle 拒绝（`must be a handle returned by process-start`） | 0（当时无 handle 概念） | **0 次** |
| "两个 selector 都给"拒绝（`provide exactly one of processRef or handle`） | 0 | **0 次** |
| 成功携带 handle 的 `process-*` tool result | 0 | **14 次 / 6 题**（meriyah 4、fastapi 3、merge-diff-arc-agi-task 3、chess-best-move 2、kv-store-grpc 1、regex-log 1） |

即：**目标缺陷从 9 次降到 0 次，且没有任何新拒绝路径被触发**，模型确实在用它刚刚启动时回显的短句柄（`p1…p4`）。这是该改动的第一次全量实证；但它**不构成 pass 率提升的证据**（见上：翻转方向相反），spec 237 自己也只声明"不主张 pass-rate 增益"。
