## 五、结论

- **本轮全量的读数是 14 passed / 14 failed / 2 error**，与基线的 18/7/5 相比：两次都有判定的 23 格里 16 → 13。`scoreable=false`、`capabilityMeasurement=false`、`passAt1=null`（因为 2 个 infra error），所以**这不是 pass@1，也不是任何 rate**。
- **工具准入没有造成任何一格失败**：36 次硬拒绝逐条正确，且没有任何一格的判定由拒绝决定。真正决定判定的是：infra 429（2）、provider 超时/传输（5）、verifier 判定（6 model + 2 spec-gap）、截止时仍在跑（1）。
- **两处可诊断性弱点**（subagent 未知引用不带补救、exec 整行 shell 不带 `sh -c` 补救）是唯一有代码证据、可验证减少浪费的工具侧问题；本轮各浪费 1–7 轮，但没有改变任何判定。
- **捕获缺口复发 1 次**：arktype 的 `model.patch` 是 0 字节，其 f2p 0/25 量的是基线树，**不能当模型结果**。
- **污染门对 2 格误判**：git-leak-recovery、merge-diff-arc-agi-task 的「答案来源」就是题目自带的 git 历史/bundle。这在 `fh_require_clean=true` 下会拒掉正确行为。

## 边界（必须随读数一起引用）

- **本 run 没有 filtered-egress 探针，也没有污染门生效**：agent 阶段是 public 网络，30 格里的 `other-network` 调用说明容器可以出网；因此**本记录不作任何「干净的模型能力读数」的声明**。任何一格要当能力读数，仍需它自己的 bounded 探针 + clean 回执，且要排除本记录 §四 指出的两类误判。
- **每格 1 次尝试**：没有重跑、没有对照臂、没有为「修好」结果而重跑；预算、超时与 effort 都没有为让格子可计分而延长。
- **不与基线的 18/7/5 合并**：两侧各自独立，本轮不产出 rate，也不改写 39557190033、39585210102、39620264048、39700728172、39721121070 的任何判定、记录或 artifact。
- **单次尝试的差值不是因果**：例如 code-from-image 从 1171s/37 calls 变成 157s/11 calls，openssl 从 passed 变 failed，都不能归因于某个具体改动。

## 尚未验证 / 未验证项

1. **候选 delta 与结果的因果关系未验证**：c38c6c843 相对 5bc13e8b5 有 120 个提交、32 个合并 PR（含 tool-contract 三批、provider proxy、apply_patch 空文件锚点）；本轮 4 格回退、1 格新增通过，只做算术并列，**没有对照臂能把任何一格的变化归因到某个切片**。
2. **2 个 error 格的镜像未 mirror**：fastapi、scc 仍走 public.ecr.aws 并被 429 限流。把这两格（以及其他未 mirror 的 datacurve 镜像）补进 digest-preserving mirror 是下一轮的前置条件，本轮未做。
3. **`costUsd=null`**：全 30 格都没有费用读数，无法给成本对照。
4. **污染分类器的漏检面未复核**：本轮只读了回执，没有独立复核它的分类逻辑；`clean` 是「未发现以该门定义的方式取到答案」，不是「已排除」。
5. **工具调用计数是下界**：取自每个格的 terminal snapshot；若运行中触发 compact，折叠前的行不在 snapshot 里。`modelCallCount` 来自 `model-outcome`（完整）。
6. **没有 per-phase 计时**：`durationMs` 是 pier trial 墙钟，容器构建、agent、verifier 三段未分开；例如 largest-eigenval 788s 里模型时长只 369s。
7. **`fh_max_parallel=8` 的影响未测**：并行度只影响排队，本轮没有对照证明它不影响任何一格的耗时分布。
8. **arktype 的 0 字节 patch 意味着这一格本轮不可作为任何读数**：它既没有可评的 patch，又撞了 1,800s 单次模型超时；要重测需要一次声明式再测，本轮按预声明「每格 1 次」不做。
